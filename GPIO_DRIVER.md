# Собственный драйвер GPIO для STM32F407

Файлы: `Core/Inc/gpio_driver.h`, `Core/Src/gpio_driver.c`.

Драйвер работает с регистрами порта напрямую. Из заголовков CMSIS
(`stm32f4xx.h`) он берёт только структуру `GPIO_TypeDef`, адреса портов
`GPIOA..GPIOI`, `RCC` и define-константы битов регистров, как разрешено
заданием. Структуры, функции и макросы HAL и LL для GPIO не используются.

## 1. Регистры порта

| Регистр   | Бит на вывод | Назначение                                              |
|-----------|--------------|---------------------------------------------------------|
| `MODER`   | 2            | режим: 00 вход, 01 выход, 10 альт. функция, 11 аналог    |
| `OTYPER`  | 1            | тип выхода: 0 push-pull, 1 открытый сток                 |
| `OSPEEDR` | 2            | скорость (крутизна фронтов)                              |
| `PUPDR`   | 2            | подтяжка: 00 нет, 01 вверх, 10 вниз                      |
| `AFR[0..1]` | 4          | номер альтернативной функции (AF0..AF15)                 |
| `IDR`     | 1            | фактический уровень на ножке (только чтение)             |
| `ODR`     | 1            | значение, которое выдаёт выход                           |
| `BSRR`    | 2            | атомарная установка (биты 0..15) и сброс (биты 16..31) битов ODR |
| `LCKR`    | 1            | блокировка конфигурации до сброса                        |

## 2. API

### Типы
* `gpio_mode_t`: `PIN_MODE_INPUT / OUTPUT / AF / ANALOG`. Значения совпадают
  с кодами поля `MODER`.
* `gpio_otype_t`: `PIN_OTYPE_PUSHPULL / OPENDRAIN`.
* `gpio_speed_t`: `PIN_SPEED_LOW / MEDIUM / HIGH / VERY_HIGH`.
* `gpio_pull_t`: `PIN_PULL_NONE / UP / DOWN`.
* `gpio_level_t`: `PIN_LEVEL_LOW / HIGH / KEEP`. Это начальный уровень выхода;
  `KEEP` оставляет ODR без изменений.
* `gpio_config_t`: все параметры вывода в одной структуре.
* `gpio_status_t`: `GPIO_OK`, `GPIO_ERR_PARAM`, `GPIO_ERR_LOCKED`, `GPIO_ERR_NO_CLOCK`.
* Маски выводов: `GPIO_PIN(n)`, `GPIO_PIN_MASK_ALL`.

У констант префикс `PIN_`, а не `GPIO_`. Иначе они совпали бы с макросами HAL
(`GPIO_MODE_INPUT`, `GPIO_PULLUP`, …), которые остаются видимыми через
`main.h → stm32f4xx_hal.h`.

### Функции

| Функция | Назначение |
|---|---|
| `gpio_init(port, pins, &cfg)` | настройка (и повторная настройка) режима сразу для нескольких выводов; включает тактирование порта |
| `gpio_deinit(port, pins)` | возврат выводов в состояние после сброса (вход, без подтяжки) |
| `gpio_get_config(port, pin, &cfg)` | чтение текущих настроек вывода из регистров |
| `gpio_read_pin(port, pin)` | чтение одного входа (0/1) |
| `gpio_read_pins(port, mask)` | одновременное чтение нескольких входов (одно чтение `IDR`) |
| `gpio_read_output(port, mask)` | чтение того, что записано в `ODR` |
| `gpio_write_pin(port, pin, v)` | запись одного выхода |
| `gpio_write_pins(port, mask, value)` | одновременная запись разных значений в несколько выходов |
| `gpio_set_pins / gpio_reset_pins / gpio_toggle_pins` | установка / сброс / инверсия группы выводов |

Функции чтения и записи объявлены как `static inline`: каждая сводится к одной
или двум инструкциям обращения к регистру.

## 3. Детали реализации

### 3.1. Вся маска выводов записывается одной операцией
`gpio_init` сначала строит маски для всех выводов (`spread2()` растягивает
16-битную маску на 2-битные поля, `field2()` заполняет эти поля значением).
Затем каждый регистр (`MODER`, `PUPDR`, …) записывается **один раз** для всей
группы. Поэтому все выводы группы меняют режим одновременно, в одном такте
шины.

### 3.2. Запись выходов через BSRR
`BSRR` устанавливает и сбрасывает биты ODR аппаратно и атомарно, без
чтения-модификации-записи. `gpio_write_pins` формирует одно слово:
биты установки берутся из `value & mask`, биты сброса — из `~value & mask`.
За одну запись несколько выводов получают **разные** значения, а остальные
выводы порта не меняются.

### 3.3. Повторная инициализация без «выбросов»
Главная опасность при смене режима — промежуточные комбинации регистров между
отдельными записями. Например, вывод был открытым стоком с уровнем 1
(высокий импеданс), а новая настройка — push-pull с уровнем 0. Если записать
сначала `OTYPER`, а потом `ODR`, то на время между записями вывод **активно
выдаст 1**. Этого уровня нет ни в старой, ни в новой конфигурации.

Правило драйвера: в промежуточном состоянии вывод выдаёт либо старое, либо
новое значение, либо высокий импеданс (это «более слабое» состояние, линию
держит подтяжка). Активный неверный уровень не появляется никогда. Порядок
записей в `gpio_init`:

1. **Смена номера AF у вывода, который уже в режиме AF.** Если записать `AFR`
   «на ходу», источник сигнала подменится мгновенно. Поэтому вывод сначала
   «паркуется»: становится обычным выходом с тем же типом, а в ODR
   записывается текущий уровень ножки из `IDR`. Затем меняется `AFR`.
2. **`OSPEEDR`, `PUPDR`, `AFR`.** Они не влияют на выдаваемый уровень. `PUPDR`
   пишется до `MODER`, поэтому новый вход сразу получает нужную подтяжку и не
   остаётся «в воздухе».
3. **Тип выхода, уровень и режим** записываются в порядке, зависящем от цели:

| Новая конфигурация | Порядок записи | Почему |
|---|---|---|
| вход / аналог | `MODER` | подтяжка уже настроена на шаге 2 |
| push-pull (выход или AF) | `BSRR(ODR)` → `MODER` → `OTYPER` | пока тип ещё старый, вывод выдаёт новый уровень, а при старом OD — Z или 0 |
| open-drain, уровень 0 | `BSRR(ODR)` → `OTYPER` → `MODER` | 0 одинаково выдаётся и в PP, и в OD |
| open-drain, уровень 1/KEEP, AF-OD | `OTYPER` → `BSRR(ODR)` → `MODER` | верхний ключ отключается до смены уровня, поэтому активная 1 не появляется |

При первичной настройке выхода (вход → выход) уровень записывается в `ODR`
**до** переключения `MODER`. Выход включается сразу с правильным значением.
В HAL для этого перед `HAL_GPIO_Init` нужно отдельно вызвать
`HAL_GPIO_WritePin`, и программист легко может об этом забыть.

### 3.4. Атомарность относительно прерываний
Регистры конфигурации меняются чтением-модификацией-записью. Если между
чтением и записью сработает прерывание и изменит другой вывод того же порта,
его изменение потеряется. Поэтому `gpio_init`/`gpio_deinit` выполняют запись
при запрещённых прерываниях: `PRIMASK` сохраняется и потом восстанавливается,
так что вложенные вызовы безопасны. Окно занимает несколько десятков тактов.
Функциям записи значений (`BSRR`) такая защита не нужна: они атомарны
аппаратно.

### 3.5. Тактирование и проверки
* `gpio_init` сам включает тактирование порта (`RCC->AHB1ENR`). После этого
  выполняется обратное чтение регистра: errata STM32F40x требует задержку
  после включения тактирования, прежде чем обращаться к периферии.
* Номер порта вычисляется по адресу (шаг 0x400 от `GPIOA_BASE`). Указатель,
  который не является портом A..I, отвергается с `GPIO_ERR_PARAM`. Так же
  отвергаются пустая маска и параметры вне допустимого диапазона.
* Выводы, заблокированные через `LCKR`, не перенастраиваются
  (`GPIO_ERR_LOCKED`). HAL в этом случае молча выполняет запись, которая
  ничего не меняет.
* `gpio_get_config` и `gpio_deinit` возвращают `GPIO_ERR_NO_CLOCK`, если порт
  не тактируется: при выключенном тактировании регистры читаются как 0.

## 4. Отличия от HAL (`stm32f4xx_hal_gpio.c`)

| | HAL | Собственный драйвер |
|---|---|---|
| Настройка группы выводов | цикл по выводам; каждый вывод переключается в свой момент | каждый регистр записывается один раз, все выводы переключаются одновременно |
| Порядок записи регистров | фиксированный: `OSPEEDR`, `OTYPER`, `PUPDR`, `AFR`, `MODER` | зависит от целевого типа выхода и уровня (п. 3.3), промежуточный активный неверный уровень исключён |
| Начальный уровень выхода | не задаётся; нужен отдельный `HAL_GPIO_WritePin` до `Init` | поле `level` в конфигурации, записывается до включения выхода |
| Смена AF «на ходу» | `AFR` меняется сразу, возможна подмена сигнала | вывод сначала «паркуется» с удержанием текущего уровня |
| Защита от прерываний при RMW | нет | да (`PRIMASK`) |
| Тактирование порта | отдельно, `__HAL_RCC_GPIOx_CLK_ENABLE()` | включается автоматически в `gpio_init` |
| Чтение текущих настроек | функции нет | `gpio_get_config` |
| Чтение нескольких входов | `HAL_GPIO_ReadPin` возвращает SET, если установлен **хотя бы один** бит маски | `gpio_read_pins` возвращает битовую маску всех уровней |
| Запись нескольких выходов | только одинаковое значение для всех выводов маски | `gpio_write_pins`: разные значения за одну запись `BSRR` |
| Возврат ошибок | `void`, проверка только `assert_param` (обычно отключён) | `gpio_status_t` |
| Блокировка (`LCKR`) | `HAL_GPIO_LockPin` есть, но `Init` её не учитывает | `Init` проверяет блокировку и сообщает ошибку |
| EXTI / прерывания | поддерживаются | не требуются заданием, не реализованы |
| Накладные расходы | вызов функции, структура `GPIO_InitTypeDef`, цикл на 16 итераций для каждого вызова | чтение/запись — `static inline`, одна-две инструкции |

## 5. Внедрение в программу стенда

* **`SDK_LED.ioc`**: из графического конфигуратора удалены выводы PD13, PD14,
  PD15 (светодиоды), PC15 (кнопка) и PA8 (MCO1). Если перегенерировать проект
  в CubeMX, их инициализация через HAL не появится.
* **`gpio.c`**: в `MX_GPIO_Init` осталось только включение тактирования
  портов, которые нужны кварцу и JTAG. CubeMX сгенерирует ровно такой код.
  Новая функция `Board_GPIO_Init()` (секция `USER CODE`, при перегенерации
  сохранится) настраивает светодиоды, кнопку и PA8 через драйвер.
* **`main.c`**: вызывается `Board_GPIO_Init()`. Удалён
  `HAL_RCC_MCOConfig(...)`: внутри он вызывал `HAL_GPIO_Init` для PA8.
  Теперь PA8 настраивается драйвером (AF0), а источник MCO1 задаётся
  напрямую битами `RCC->CFGR`.
* **`lock.c`**: `HAL_GPIO_WritePin / TogglePin / ReadPin` заменены на
  `gpio_write_pin / gpio_toggle_pins / gpio_read_pin`. Все три светодиода
  гасятся одной записью `gpio_reset_pins`.
* **`i2c.c`, `usart.c`**: выводы I2C1 (PB8/PB9, AF4, открытый сток) и USART6
  (PC6/PC7, AF8) настраиваются через `gpio_init`. `HAL_GPIO_DeInit` заменён
  на `gpio_deinit`.

Макрос `HAL_GPIO_MODULE_ENABLED` в `stm32f4xx_hal_conf.h` оставлен включённым:
без него не компилируется HAL RCC, который ссылается на `GPIO_InitTypeDef`.
Функции HAL GPIO при этом нигде не вызываются, и в прошивку они не попадают:
в `SDK_LED.elf` нет символов `HAL_GPIO_*`, их удаляет линкер (`--gc-sections`).
